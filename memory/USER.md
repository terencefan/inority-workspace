## 文档写作

- `aiready` 是固定术语：普通小写写作 `aiready`，大写、标题或专名写作 `AIReady`；
  不写成 `ai-ready`、`AI-Ready` 或 `AIREADY`。
- blockquote 保持简洁，优先只写一句。
- blockquote 必须写多句时分行表达。
- 编写文档时不使用分号。需要用分号分隔的并列内容改写为列表。
- 文档标题只使用文字，不添加 `x.y.z`、`1.2.3` 等多级数字序号。
- 调查结果、地址映射、资源清单、状态清单和其他事实型交付物默认生成项目内
  `.md` 文件，并使用 `write-doc` 的 report 链路。只有明确指定飞书或其他外部
  工具时，才切换交付位置或格式。
- 同一目标下发生 r1、r2 等多轮重试时，只维护一份迭代决策报告。报告按轮次持续
  追加假设、证据、失败原因、决策和下一步，保留完整决策链，不为每轮拆分报告。
- 需要为代码或工具补文档时，优先维护对应 folder 下的 `README.md`，避免先创建
  远离实现目录的独立说明文档。
- 当发现文档或资产与线上状态、目标环境不一致时，必须同步更新对应的 authority
  文档或资产，不能只修改线上环境或仅报告漂移。
- 更新飞书文档时，如果漂移检查仅发现 revision 变化、线上正文没有变化，默认直接刷新基线后发布，不再询问合并路径。若线上正文确有变化，仍先生成差异并确认合并方式，避免覆盖人工编辑。

- 后续出网请求和镜像构建优先使用实验室 HTTP 代理，Python 依赖优先使用实验室
