# 工作原理

K8s 的工作原理可以从 kubelet、api-server 和 controller 三个角度来理解：

1. kubelet：运行在每个节点上的核心代理，负责把节点上应该运行的 Pod 真的拉起并持续汇报状态。
2. api-server：整个集群的统一入口，负责接收用户提交的声明式配置，并把它保存成集群当前的期望状态。
3. controller：控制器负责持续监听资源对象，并通过内部的 reconcile 过程不断比较“期望状态”和“实际状态”，只要发现偏差，就会继续采取动作把系统拉回目标状态。

把三者串起来看，就是用户先把需求写进 api-server，再由 controller 持续驱动控制循环，并在内部通过 reconcile 机制判断哪里与目标不一致，最后由 kubelet 在具体节点上执行容器启动、重建和状态回报，最终形成一个持续收敛的自动化控制闭环。
