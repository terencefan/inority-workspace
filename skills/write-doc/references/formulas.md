# Markdown 公式

## 写作规则

1. 先用正文说明公式回答什么问题，再给公式；公式后紧接变量、单位和适用条件。
2. 短表达式使用行内 `$...$`。需要独占一行、换行、对齐或包含分式的公式，handbook 文档优先使用 fenced `katex`；`math` 是等价别名。
3. 同一符号在全文保持同一含义，公式符号必须与表格列名、脚本变量和统计口径对应。首次出现时定义，不依赖读者猜测。
4. 不编造公式、参数或计算结果。统计方法不确定时先核对脚本、数据资产或权威定义；无法确认则明确标注待验证。
5. 公式必须有文字解释，不能只靠视觉排版表达结论。复杂推导拆成多个有语义的公式块。
6. 使用 KaTeX 支持的标准 LaTeX；避免自定义宏、外部包、HTML 注入和依赖可信执行的命令。

## 推荐语法

行内公式：

```markdown
吞吐量记为 $R=N/T$，单位为 img/s。
```

展示公式：

````markdown
```katex
R_j=\frac{N_j}{T_j}
```
````

其中，$N_j$ 为第 $j$ 轮成功样本数，$T_j$ 为对应墙钟时间（秒）。

仅当目标渲染器不支持 fenced `katex`、但明确支持数学定界符时，才使用：

```markdown
$$
R_j=\frac{N_j}{T_j}
$$
```

## 交付检查

- 确认目标渲染器支持所选语法；handbook 使用 fenced `katex` 或 `math`。
- 实际打开或构建目标文档，检查公式已渲染且没有 KaTeX 错误提示、截断或横向溢出。
- 对照结果表和计算脚本检查符号、分母、单位、样本量、区间端点与舍入规则。
- 保留计算脚本或数据资产链接；公式描述方法，资产提供可复算证据。
- 纯文本消费者仍应能从公式前后的文字理解指标含义和结论。
