## 背景

说明这次故障分析发生在什么上下文里，为什么需要这份 RCA。

## 现象与影响

- 用户可见现象
- 影响范围
- 未受影响范围

## 调查范围与方法

- 环境边界
- 只读还是可变更
- 关键命令 / 探针类型

## 侦察结论

### 控制面请求可以到达 worker，但 worker 没有继续下发任务

> 这说明入口链路健康，故障收敛在 worker 内部队列或调度环节。

可复现方法：

- 进入 `prod-worker-1`
- 执行 `journalctl -u worker --since "10 min ago"`
- 连续观察 3 次任务触发窗口，确认入口日志存在而任务下发日志缺失

## 已排除的故障原因

### 入口 DNS 故障

排查步骤：

1. 在入口 Pod 内执行 `curl -I https://service.example/api/health`
2. 在 worker 宿主机执行相同请求

排除原因：

- 两侧都返回 `200`
- 无解析失败或连接超时

## 当前结论

- 已由证据支持的事实：入口到 worker 的请求链路健康。
- 当前更合理的工程推断：worker 内部队列消费或调度状态异常。

## 仍未证实的部分

- 是否存在特定任务类型才会触发该问题
- 是否与本次发布引入的队列参数变更直接相关

## 复现步骤

- 前置条件：准备一条新的同步任务
- 最小复现：触发任务后观察 worker 日志
- 健康对照：在 staging 环境重复同样步骤

## 建议的下一步

1. 增加 worker 队列消费状态的只读探针
2. 对比本次发布前后的 worker 调度配置
3. 在 staging 复现同类任务，确认是否与数据规模相关
