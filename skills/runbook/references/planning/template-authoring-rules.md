# Authority Runbook 编写规则

本文件承接 `authority-runbook-template.md` 中不应出现在最终交付文档里的作者指导语。模板只定义文档结构，本文件定义填写与定稿规则。

## 现状与目标

- `### 现状` 必须来自本轮真实侦察或用户刚提供的新证据。历史结论只能作为明确标注的背景。
- 前提、入口、地址和边界并入现状，不新增 `## 当前前提`。
- 工具有原生 dry-run、no-op、plan 或 diff 时，应执行只读预演并记录退出码和关键输出。无法执行时说明原因。
- 现状图、目标图和思维脑图必须与正文的唯一执行路径一致。

## 资源与风险

- `## 资源命名` 列出规划者确定的 namespace、release、cluster、StorageClass、topic、user、Secret、label，以及飞书消息标题、目标群或接收人、卡片模板标识等资源名。
- 没有资源需要命名时可以写 `资源命名：不适用`，并填写不适用原因。
- 适用与不适用两种场景都必须由用户明确确认，确认后才能勾选 checkbox。
- 风险和收益只保留 authority 定稿后仍然存在并会影响执行、回滚或验收的内容。

## 思维脑图与红线

- 思维脑图根节点直接引用用户原始需求，至少包含 3 个边界或选型问题，每个问题至少包含 2 个已固化结论。
- 叶子节点写结论，不写问题。所有节点手动换行。
- `## 红线行为` 只保留红线条目和必要的禁止命令，不增加三级标题。

## 清理现场

- 清理章节定义停止后的清理触发条件、命令、完成条件和恢复执行入口。
- 执行记录只保留恢复后的成功路径，不累计中断分支的失败清理尝试。
- 没有中断残留风险时可以写 `清理策略：不适用`，但必须填写不适用原因，且不得同时保留清理命令。

## 执行计划

- operation 模式首项为“冻结现状”。迁移场景也使用 operation，并在执行计划中显式定义 source、target、cutover 和 rollback。
- 每个编号项只有一个 `#### 执行` 和一个 `#### 验收`，编号连续，计划与记录标题一一对应。
- 操作性质、标题灯号和 GitHub alert 必须一致。只读使用 🟢 和 TIP，幂等使用 🟡 和 WARNING，破坏性使用 🔴 和 CAUTION。
- 破坏性步骤额外写一个严重后果 CAUTION，并在回滚章节提供同序号回滚条目。
- 宿主机网络、磁盘、cgroup 等底层配置变更一律视为破坏性。
- 不同操作性质或不同机器 scope 拆成独立编号项。
- 验收命令必须可直接执行并自行完成判定。判定标准写明退出码及精确字段、返回值、计数、阈值或可验证状态。
- 编号项验收不使用 checkbox。所有完成 checkbox 统一放到最终验收。

## 执行记录

- 未执行和未验收时保留未签名记录，不预签 planning 阶段的侦察证据。
- 真实执行时使用 `#### 执行记录 @名字 YYYY-MM-DD HH:MM TZ` 和 `#### 验收记录 @名字 YYYY-MM-DD HH:MM TZ`。
- 中断后的清理动作写入清理章节，记录区只保留恢复后的成功路径。

## 最终验收与回滚

- 最终验收由独立上下文的只读 recon 重新取证，不复用编号项执行和验收记录作为完成证据。
- authority 声明覆盖整个集群或多个主机波次时，最终验收必须重新覆盖所有声明范围，不能只复核此前失败的波次。
- 主 rollout 只向 recon 提供 authority 路径、侦察问题、只读边界和待确认事实。
- 最终验收通过后，用独立证据更新对应 spec，再执行 `runctl validate <path> --final`。
- 回滚章节位于最终验收之后，包含回滚边界、动作和最小验证，不增加三级标题。

## 访谈与参考资料

- 访谈记录至少保存 3 条 planning 阶段真实发生的用户问答，不允许作者自问自答，也不允许为满足数量制造问答。
- 问题和回答正文与标题同行。回答后记录访谈时间，再分行记录影响面。
- 参考资料只使用 `name/type/link/desc` 四列表格。
